`@totalistrading/hip4-client` is the TypeScript SDK for the Hyperliquid API, version 0.14.0. It is the
client the Totalis app runs. It holds typed clients for every route, the taker and maker flows end to
end, the messages each flow signs, a request layer that resends safely, pagination and the stream. It
never stores a key: every signature goes to the signer you pass in.

## Access and install

The SDK is private. Access is provided on request: email
[founders@totalis.trade](mailto:founders@totalis.trade) with the GitHub account that should read it.
Once access is granted, point the `@totalistrading` scope at GitHub Packages with a token that can read
packages, and install:

```ini .npmrc
@totalistrading:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${GITHUB_TOKEN}
```

```bash
npm install @totalistrading/hip4-client@0.14.0 viem
```

One ESM package runs in Node 22 or later and in browsers. It has no wallet dependency. `viem` (or
ethers) is only needed to turn a private key into a signer. Without SDK access, every guide's raw API
steps work as plain HTTP.

| Import | Holds |
| --- | --- |
| `@totalistrading/hip4-client` | `createTotalis` (taker flows), `createClient` (typed client for every personal and public route), `bestQuote` and `bestBid` (the default choosers), `ApiError`, `NetworkError`, `pages` and `items`, `toTotalisSigner`, `TotalisStream`, `uuidv7` |
| `@totalistrading/hip4-client/maker` | `createMaker` (maker flows), `createMakerClient` (typed client for maker routes), and the controller's vault transactions |
| `@totalistrading/hip4-client/realtime` | `TotalisStream` and the generated stream frame types |
| `@totalistrading/hip4-client/typed-data` | Builders and hashing for every signed message, from the API's own JSON shapes. See [Signing](/hyperliquid/signing). |
| `@totalistrading/hip4-client/signer` | `toTotalisSigner` for viem accounts and wallet clients, EIP-1193 providers and ethers signers |
| `@totalistrading/hip4-client/errors` | The generated error registry, `ApiError` and `NetworkError` |
| `@totalistrading/hip4-client/api-keys` | Key issuance and rotation for apps with a signed-in user session |

## Clients

| Function | Calls | Credential | Signer |
| --- | --- | --- | --- |
| `createClient(environment, options)` | Any personal or public route, typed | Optional personal key | None |
| `createTotalis(options)` | `openPosition`, `cashOut`, `withdraw`, `signWithdrawal`, `sendWithdrawal`, `waitForWithdrawal`, `waitForOperation`, `watchQuotes`, `deployment` | Personal key | Your Totalis wallet (`wallet` in `GET /v1/me`) |
| `createMakerClient(environment, options)` | Any maker route, typed | Maker key | None |
| `createMaker(options)` | `onRfq`, `quote`, `bid`, `cancelQuote`, `onAcceptance`, `confirm`, `deployment`, `controller`, `reduceCollateral` | Maker key | The maker's quote signer |

`environment` is `"production"` or `"staging"`. Pass `baseUrl` to point at another origin. Money is
integer USDC atomic units, as a `bigint` or a decimal string: `25_000_000n` is 25 USDC.

`createTotalis` and `createMaker` also expose `client`, the typed client over the same key, and
`stream`, the subscription the flows follow. Call `close()` when you are done.

## Signers

Every flow that signs takes a `signer`. Pass any of these:

| Signer | Example |
| --- | --- |
| viem local account | `privateKeyToAccount(process.env.TOTALIS_WALLET_KEY)` |
| viem wallet client | `createWalletClient({ account, transport })` |
| EIP-1193 provider | `window.ethereum`, or an embedded wallet's provider |
| ethers v6 signer | `new Wallet(privateKey)` |

The SDK signs only what the flow you called needs, and checks the terms first. `openPosition` signs
only quotes for exactly your taker, stake and legs. `cashOut` signs only quotes for your position and
owner. `withdraw` signs a payout only for your destination and amount. A maker's quote signer signs
only terms that maker created and that have not expired.

## Retries and errors

Every command is built once, with its `Idempotency-Key`, and resent byte for byte after a network
failure or a `BACKOFF` error, after `Retry-After` or a jittered backoff. That is five sends by default.
Set `retry: { attempts }` to change it, or `retry: false` to send once. The venue replays a command it
already accepted, so a resend never opens a second position or a second withdrawal.

`unwrap(result)` returns a typed client's data or throws `ApiError` with the registered `code`,
`retry`, `status`, `requestId`, `fieldViolations` and `retryAfterMs`. What each `retry` value means is
on [Errors](/hyperliquid/errors).

```ts
import { ApiError, createTotalis, NetworkError } from "@totalistrading/hip4-client";
import { privateKeyToAccount } from "viem/accounts";

const totalis = createTotalis({
  environment: "production",
  accessToken: process.env.TOTALIS_API_KEY!,
  signer: privateKeyToAccount(process.env.TOTALIS_WALLET_KEY as `0x${string}`),
});

try {
  await totalis.openPosition({ legs: [{ outcome_id: "1209", side: "YES" }], stake: 25_000_000n });
} catch (error) {
  if (error instanceof NetworkError || (error instanceof ApiError && error.retry === "BACKOFF")) {
    await error.resend?.(); // same bytes, same Idempotency-Key: never a second accept
  } else if (error instanceof ApiError && error.retry === "REFRESH") {
    // re-read the state the command depends on, then decide on a new command
  } else if (error instanceof ApiError) {
    console.error(error.code, error.status, error.requestId, error.fieldViolations); // NEVER: stop
  } else {
    throw error;
  }
}
```

`NetworkError` means the outcome is unknown. For a flow's command, it and a `BACKOFF` error that
outlasted the resends carry `resend()`, which sends the identical request again and returns the
venue's result. Never sign a second command instead.

## Changes in 0.14.0

0.14.0 is breaking and needs contract 118. It moves the SDK to the vocabulary on
[Glossary](/hyperliquid/glossary). Signed messages, digests and signatures are unchanged.

| 0.13.0 | 0.14.0 |
| --- | --- |
| `placeBet` | `openPosition`. It returns `{ rfqId, acceptanceId, quoteId, positionId, entry, status, operationId, outcome }`. |
| `cashOut({ ticketId })` | `cashOut({ positionId })`, which calls [Cash out position](/hyperliquid/api-reference/positions/cash-out-position) |
| `watchBook` | `watchQuotes` |
| `release()` | `deployment()`, from [Get deployment](/hyperliquid/api-reference/deployment/get-deployment) |
| `maker.withdraw(rfqId, digest)` | `maker.cancelQuote(quoteId)` |
| `maker.onConfirmation` | `maker.onAcceptance` |
| `state` | `status`, on every lifecycle field |
| Legs `{ outcome_id: 1209, side: 0 }` | `{ outcome_id: "1209", side: "YES" }` |
| `ticket_id`, `quote_digest`, `attempt_id` | `position_id`, `quote_id`, `acceptance_id` |
| Types `BookQuote`, `Confirmation`, `Release`, `MakerConfirmationRequest` | `Quote`, `Acceptance`, `Deployment`, `MakerAcceptance` |
| Stream option `topic` | `subscription: { type: "account" }` or `{ type: "maker", maker_id }` |
| Scopes `ticket:accept`, `ticket:cashout` | `quote:accept`, `position:cashout` |

The complete list ships in the package as `CHANGELOG.md`.

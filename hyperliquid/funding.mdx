Your Totalis balance on HyperEVM has two parts:

| Part | What it is |
| --- | --- |
| **Wallet** (`WALLET_USDC`) | USDC held by your Totalis wallet, the embedded wallet in `GET /v1/me`. |
| **Vault** (`VAULT_FREE`) | Your unreserved USDC inside the Totalis vault contract. Stakes are taken from it, and payouts and cashouts are paid into it. |

Totalis pays the gas for deposits and withdrawals, so your wallet needs no HYPE. Every movement of
money also carries a signature from your wallet, which the SDK makes with the signer you pass. The
examples use the `totalis` client from [Trading](/hyperliquid/trading#1-create-a-client).

| To | SDK | Key scopes | You sign |
| --- | --- | --- | --- |
| Move wallet USDC into the vault | `deposit` | `funding:deposit`, `sponsorship:use` | USDC `ReceiveWithAuthorization` |
| Send USDC to any address | `withdraw` | `funding:withdraw`, `sponsorship:use`, `account:read`, `account:stream` | Vault `Exit` for any shortfall, then USDC `TransferWithAuthorization` |

## Read your balance

[Get balances](/hyperliquid/api-reference/account/get-balances) returns one balance, `TOTALIS`:

```ts
import { unwrap } from "@totalistrading/hip4-client";

const { balances: [totalisBalance] } = unwrap(await totalis.client.GET("/v1/me/balances"));
console.log(totalisBalance?.amount, totalisBalance?.components); // WALLET_USDC and VAULT_FREE
```

```json
{
  "balances": [
    {
      "product": "TOTALIS",
      "amount": "37500000",
      "unit": "USDC_BASE_UNITS",
      "state": "CURRENT",
      "components": [
        { "kind": "WALLET_USDC", "amount": "12500000", "state": "CURRENT" },
        { "kind": "VAULT_FREE", "amount": "30000000", "state": "CURRENT" }
      ],
      "pending": {
        "wallet_reserved": "5000000",
        "vault_deposits": "0",
        "vault_withdrawals": "0",
        "core_exits": "0",
        "has_unknown_operations": false
      }
    }
  ],
  "checkpoint": { "chain_id": "999", "block_number": "31552210", "projection_state": "CURRENT" }
}
```

`amount` is what you can spend: wallet USDC plus vault USDC, minus wallet USDC already reserved by
pending work, never below zero. It is `null` unless `state` is `CURRENT`. The response holds the
Totalis balance only. HyperCore balances are not part of it. Read them from Hyperliquid, or with
[Get HyperCore portfolio](/hyperliquid/api-reference/hypercore/get-hypercore-portfolio).

## Get USDC into your wallet

Send native USDC on HyperEVM (chain ID `999`) to your wallet address. The token is
`0xb88339cb7199b77e23db6e890353e22632ba630f`. To fund from another chain, deposit in the
[Totalis app](https://totalis-hip4.vercel.app), which bridges it for you.

You do not have to move it into the vault yourself. `placeBet` tops up a vault shortfall from your
wallet in the same accept, unless you pass `funding: "none"`.

## Deposit into the vault

```ts
const deposit = await totalis.deposit({ amount: 10_000_000n }); // 10 USDC, wallet to vault
await totalis.waitForOperation(deposit.operation_id);
```

`deposit` signs a USDC `ReceiveWithAuthorization` that pays the vault and submits it to
[Deposit](/hyperliquid/api-reference/funds-and-tickets/deposit). The `202` response, with
`state: "DURABLE"`, means the deposit is queued, not that it landed. `waitForOperation` resolves
when the operation is terminal: `COMMITTED`, `REVERTED`, or `EXPIRED_UNEXECUTED`.

Without the SDK, build the authorization with `receiveWithAuthorizationTypedData(release, authorization)`
from `@totalistrading/hip4-client/typed-data`, sign it with your wallet, and send the authorization
fields plus `authorization_signature` as the command. The builder derives the USDC nonce from your
`salt`, your address, and the vault, exactly as the vault checks it. The authorization window rules
are on [Limits and timing](/hyperliquid/conventions#limits-and-timing).

## Withdraw to any address

```ts
const done = await totalis.withdraw({
  destination: "0x2222222222222222222222222222222222222222",
  amount: 15_000_000n,
  onStarted: (continuationId) => console.log("save", continuationId), // persist before it continues
});
console.log(done.state, done.payout_transaction_hash); // PAYOUT_COMMITTED
totalis.close();
```

A withdrawal pays out from your wallet. If the wallet does not hold enough, `withdraw` first signs a
vault `Exit` for exactly the shortfall, back to your own wallet. When the wallet is credited, it
claims the payout, signs a USDC `TransferWithAuthorization` for exactly your destination and amount,
and resolves once the transfer is final. Each step is woken by the stream.

`onStarted` receives the withdrawal's `continuation_id` before anything else happens. Persist it. If
your process restarts, continue the same withdrawal instead of starting a second one:

```ts
await totalis.resumeWithdrawal({
  continuationId: "01998683-7a31-7e5a-a3c1-6f2b8d4e9a17",
  destination: "0x2222222222222222222222222222222222222222",
  amount: 15_000_000n,
});
```

The SDK signs the payout only if the withdrawal the venue returns still has your destination and
amount.

| `state` | Meaning |
| --- | --- |
| `VAULT_WITHDRAWAL_QUEUED`, `AWAITING_WALLET_CREDIT`, `UNKNOWN` | The vault shortfall is moving to your wallet. |
| `READY_FOR_PAYOUT_CLAIM` | Your wallet holds the amount. The payout can be claimed. |
| `AWAITING_PAYOUT_SUBMISSION` | The payout is claimed. `wallet_transfer` holds the exact transfer to sign. |
| `PAYOUT_SUBMITTED` | Totalis is relaying the signed transfer. |
| `PAYOUT_COMMITTED` | Done. `payout_transaction_hash` is set. |
| `FAILED` | The withdrawal stopped. Read your balance and start a new one. |

### Without the SDK

<Steps>
  <Step title="Start the withdrawal">
    [Create Totalis withdrawal](/hyperliquid/api-reference/funds-and-tickets/create-totalis-withdrawal)
    with `account`, `destination`, and `amount`. If your wallet cannot cover `amount`, add
    `vault_withdrawal`: an `Exit` from the vault to your own wallet for exactly the shortfall, signed
    with `exitTypedData`. A shortfall that no longer matches returns `STATE_CONFLICT`: re-read your
    balance and sign again.
  </Step>
  <Step title="Wait for the wallet credit">
    Follow `TOTALIS_WITHDRAWAL_CONTINUATION_UPDATED` events until the state is
    `READY_FOR_PAYOUT_CLAIM`. After a reconnect, read
    [Get Totalis withdrawal](/hyperliquid/api-reference/funds-and-tickets/get-totalis-withdrawal).
  </Step>
  <Step title="Claim the payout">
    [Claim Totalis withdrawal payout](/hyperliquid/api-reference/funds-and-tickets/claim-totalis-withdrawal-payout)
    returns `wallet_transfer`, the exact transfer to sign.
  </Step>
  <Step title="Sign and submit it">
    Sign it with `transferWithAuthorizationTypedData(wallet_transfer, { valid_after, valid_before })`
    and send `valid_after`, `valid_before`, and `authorization_signature` to
    [Record Totalis payout submission](/hyperliquid/api-reference/funds-and-tickets/record-totalis-payout-submission).
    Follow events until `PAYOUT_COMMITTED`.
  </Step>
</Steps>

To withdraw straight from the vault to any address in one step, sign an `Exit` to that address and
send it to [Withdraw](/hyperliquid/api-reference/funds-and-tickets/withdraw). The SDK has no flow for
this route. Build the message with `exitTypedData`.

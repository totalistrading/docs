An `account` subscription streams your own account: your RFQs and the quotes on them, your acceptances,
operations, positions, balances and withdrawals. Takers open positions, cash out and withdraw on it. How
to connect, apply events and resume is on [Connect and resume](/hyperliquid/streams).

| | Value |
| --- | --- |
| Key | Personal key with `account:stream` |
| Resume from a cursor | Also needs `replay:read` |
| Every open RFQ, not only yours (`open_rfqs`) | Also needs `rfq:read` |
| SDK | `totalis.stream`, or `new TotalisStream({ subscription: { type: "account" }, ... })` |

## Subscribe frame

```json
{
  "method": "subscribe",
  "subscription": {
    "type": "account",
    "publication_freshness": true
  }
}
```

| Field | Required | Meaning |
| --- | --- | --- |
| `type` | Yes | Always `account`: the account your key acts for. |
| `cursor` | No | Your last applied cursor, to resume after it. Omit it to start from a snapshot. |
| `open_rfqs` | No | `true` to receive every open RFQ, as `open_rfqs` in the snapshot and as RFQ events. Without `rfq:read` the server closes with `SUBSCRIPTION_DENIED`. |
| `account_reads` | No | `true` to receive `readInvalidated` frames when an account read changes. |
| `publication_freshness` | No | `true` for a 1000 ms heartbeat and `publication` checkpoints. The SDK turns it on for an account. |

## Response

```json
{
  "channel": "subscriptionResponse",
  "data": {
    "method": "subscribe",
    "subscription": { "type": "account", "publication_freshness": true },
    "connection_id": "0199a1c8-7f01-7d10-9a2b-3c4d5e6f7081",
    "server_time": "2026-09-26T20:00:00.412Z",
    "heartbeat_interval_ms": 1000,
    "resume": "SNAPSHOT",
    "cursor": {
      "stream_id": "0199a1c2-3b4d-7e5f-8a6b-1c2d3e4f5a60",
      "generation_id": "0199a1c2-3b4d-7e5f-8a6b-1c2d3e4f5a61",
      "sequence": "184240"

```

With `account_reads`, the response also carries `account_reads`, the scope the server derived.

## Snapshot

| Class | Holds | `href` when `truncated` |
| --- | --- | --- |
| `rfqs` | Your RFQs | `/v1/rfqs`, [List RFQs](/hyperliquid/api-reference/rfqs/list-rfqs) |
| `quotes` | The live quotes on your open RFQs, the same items as `QUOTE_CREATED` | `/v1/rfqs/{rfq_id}/quotes`, [List quotes](/hyperliquid/api-reference/quotes/list-quotes) for each open RFQ |
| `acceptances` | Your acceptances still `PENDING_CONFIRM` or `PENDING_FUNDING` | `/v1/quotes/{quote_id}/acceptance`, [Get acceptance](/hyperliquid/api-reference/quotes/get-acceptance) for each quote you accepted |
| `operations` | Your operations | `/v1/me/operations`, [List operations](/hyperliquid/api-reference/account/list-operations) |
| `open_rfqs` | Every open RFQ. Only with `open_rfqs: true`. | `/v1/rfqs`, [List RFQs](/hyperliquid/api-reference/rfqs/list-rfqs) |

```json
{
  "channel": "snapshot",
  "data": {
    "cursor": { "stream_id": "0199a1c2-3b4d-7e5f-8a6b-1c2d3e4f5a60", "generation_id": "0199a1c2-3b4d-7e5f-8a6b-1c2d3e4f5a61", "sequence": "184240" },
    "resources": { "rfqs": [], "quotes": [], "acceptances": [], "operations": [] }
  }
}
```

`truncated` is absent when nothing was cut short. Read balances and positions over HTTP when you
connect: they are not snapshot classes.

## Events

| Event | When | Payload |
| --- | --- | --- |
| `RFQ_CREATED` | You created an RFQ, or any RFQ opened with `open_rfqs` | The whole open RFQ, as [Get RFQ](/hyperliquid/api-reference/rfqs/get-rfq) returns it, without `status`. `kind` is `ENTRY` or `CASHOUT`. |
| `RFQ_ACCEPTED`, `RFQ_CANCELLED`, `RFQ_FAILED` | An RFQ had a quote accepted, was cancelled, or its trade failed on-chain | `rfq_id`, `status`, `terminal_reason` (`REVERTED` or `EXPIRED_UNEXECUTED` for `FAILED`, else `null`), `created_at`, `expires_at` |
| `QUOTE_CREATED` | A maker created a quote on your RFQ | The whole quote: `quote_id`, `rfq_id`, `kind`, `sequence`, and `entry`, `sell_back` or `transfer`. Accept it by `quote_id`. |
| `QUOTE_REMOVED` | A quote left your RFQ | `rfq_id`, `quote_id`, `status`: `CANCELLED`, `REPLACED` or `ACCEPTED`. Expiry sends no event. |
| `OPERATION_UPDATED` | An operation (an accept, sell-back, transfer or payout) changed status | `operation_id`, `kind`, `status`, `transaction_hash`, `updated_at` |
| `POSITION_OPENED` | A trade you accepted filled | `position_id`, `block_number`, `log_index`. Read the position. |
| `POSITION_TRANSFERRED` | A position changed owner in a cash-out | Same as above. The previous owner receives it too. |
| `POSITION_SETTLED` | A position was graded | Same as above |
| `POSITION_CLOSED` | A position was claimed or sold back | Same as above |
| `POSITION_UPDATED` | Any other on-chain change to a position | Same as above |
| `VAULT_BALANCE_CHANGED` | A committed transaction changed your vault balance | `address`, `amount` (the balance after, not the change), `transaction_hash`, `status: COMMITTED` |
| `WALLET_BALANCE_CHANGED` | A USDC transfer touched your wallet | `address`, `transaction_hash`, `block_number`. Read [Get balances](/hyperliquid/api-reference/account/get-balances). |
| `WALLET_FUNDING_UPDATED` | The wallet funding of an acceptance changed | `acceptance_id`, `status`, `updated_at` |
| `CORE_FUNDING_UPDATED` | The HyperCore funding of an acceptance changed | `acceptance_id`, `status`, `updated_at` |
| `WITHDRAWAL_UPDATED` | A withdrawal was admitted or changed status | The whole withdrawal, as [Get withdrawal](/hyperliquid/api-reference/withdrawals/get-withdrawal) returns it |
| `CORE_EXIT_UPDATED` | A HyperCore exit changed | `exit_id`, `status`, `updated_at` |
| `HYPERCORE_WITHDRAWAL_UPDATED` | A HyperCore withdrawal changed | `operation_id`, `status`, `updated_at` |

Maker events (`QUOTE_ACCEPTED`, `MAKER_CAPITAL_UPDATED`, `COLLATERAL_REDUCTION_UPDATED`) never reach an
account subscription.

## Which frames need which scope

| Frames | Needs |
| --- | --- |
| Account frames: everything above except other accounts' RFQs | `account:stream` |
| Every open RFQ (`open_rfqs`) | `rfq:read` |
| Replay after a cursor | `replay:read` |

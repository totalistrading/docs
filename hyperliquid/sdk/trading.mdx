`createTotalis` runs every taker action in one call. Each call gets the signatures it needs from your signer,
sends the command, and follows it until it ends.

## Quickstart

```ts
import { createTotalis } from "@totalis/hip4-client";
import { privateKeyToAccount } from "viem/accounts";

const totalis = createTotalis({
  environment: "production",
  accessToken: process.env.TOTALIS_API_KEY!,
  signer: privateKeyToAccount(process.env.TOTALIS_WALLET_KEY as `0x${string}`),
});

await totalis.deposit({ amount: 50_000_000n }); // 50 USDC from the wallet into the vault

const opened = await totalis.openPosition({
  legs: [
    { outcome_id: "1209", side: "YES" },
    { outcome_id: "1344", side: "NO" },
  ],
  stake: 25_000_000n, // 25 USDC
});
const operation = opened.operationId ? await totalis.waitForOperation(opened.operationId) : undefined;

if (operation?.status === "COMMITTED") await totalis.cashOut({ positionId: opened.positionId });

await totalis.withdraw({ destination: "0x2222222222222222222222222222222222222222", amount: 15_000_000n });

await totalis.close();
```

The signer must be the account's wallet. In a browser, pass `window.ethereum` or a wallet client instead
([Wallets and partners](/hyperliquid/sdk/wallets)).

| Call | Does | Resolves |
| --- | --- | --- |
| `deposit({ amount })` | Moves wallet USDC into the vault. Totalis pays the gas. | The deposit's operation, once it ends |
| `openPosition({ legs, stake })` | Creates the RFQ, takes the best quote and funds the stake | Once the maker answers |
| `cashOut({ positionId })` | Requests bids for the position and takes the best one | Once the maker answers |
| `withdraw({ destination, amount })` | Pays USDC out to any address | At `PAYOUT_COMMITTED` |
| `exitToCore({ amount })` | Moves vault cash to the account's HyperCore spot balance | Once the exit is admitted |

To store each signed message before it is sent, so a reload never signs twice, use the step-by-step functions
on [Advanced: custom signing and recovery](/hyperliquid/sdk/resume-and-retry).

## Open a position

```ts
const opened = await totalis.openPosition({
  legs: [
    { outcome_id: "1209", side: "YES" },
    { outcome_id: "1344", side: "NO" },
  ],
  stake: 25_000_000n, // 25 USDC
});

if (opened.operationId) {
  const operation = await totalis.waitForOperation(opened.operationId);
  console.log(operation.status); // COMMITTED when the position opened
}
```

Legs go in strictly ascending `outcome_id` order. `openPosition`:

1. Waits for the account stream, then creates the RFQ.
2. Has the wallet sign any funding the vault is short of, while quotes arrive.
3. Collects quotes for `collectMs` and picks one with `choose`.
4. Has the wallet sign `TakerAccept` for it and sends the accept at once. If the answer is lost, it recovers
   the accept.
5. If the quote was just replaced, or the maker declined it or didn't answer, nothing traded. It takes the best
   other quote paying at least `minPayout`, waiting up to `quoteTimeoutMs` for one, and tries again with its own
   funding signature. It stops after `maxAttempts` accepts.

A quote stays takeable while it is listed. Makers replace their quotes as their prices move, so step 5 is what
keeps a slow wallet from losing the trade.

It returns once a maker answers. `status` says what happened:

| `status` | Meaning |
| --- | --- |
| `ACCEPTED` | The maker confirmed. Follow `operationId` with `waitForOperation`. |
| `DECLINED`, `TIMED_OUT` | Nothing traded, and no other quote paying at least `minPayout` came in time |
| `CANCELLED` | Nothing traded |
| `NOT_ADMITTED` | Every response was lost and the venue had no acceptance, so the SDK cancelled the RFQ. Nothing traded. |
| `FILLED`, `FAILED` | Only after a lost answer is recovered: the trade had already committed, or already failed |

When it gives up without a fill, `openPosition` cancels the RFQ. The result also carries `rfqId`, `acceptanceId`,
`quoteId`, `positionId`, the signed entry `record`, and `bridged` and `bridging` for an entry that bridged cash
from HyperCore ([Entry records](/hyperliquid/sdk/resume-and-retry#entry-records-and-the-bridge)).

An accepted entry is not open yet. `waitForOperation` ends `COMMITTED` when it opened, or `REVERTED` or
`EXPIRED_UNEXECUTED` when nothing traded.

### Options

| Option | Default | Does |
| --- | --- | --- |
| `legs` | | The legs, in ascending `outcome_id` order |
| `stake` | | The stake in atomic USDC |
| `quoteTimeoutMs` | 20,000 | How long to wait for an acceptable quote, the first and each later one. With none in time, the RFQ is cancelled. |
| `collectMs` | 1,000 | How long to keep collecting after the first quote `choose` would take. `0` takes it at once. |
| `choose` | `bestQuote()` | `(quotes) => quote`: picks one of the listed quotes, or returns `undefined` to keep waiting |
| `funding` | `"wallet"` | `"wallet"` funds the exact shortfall from the wallet; `"approval"` draws it from the wallet's [approval](/hyperliquid/sdk/resume-and-retry#wallet-approval); `"none"` never funds; a funding command you built is sent as is |
| `core` | | HyperCore spot USDC you offer to bridge to the wallet when its HyperEVM USDC falls short |
| `cash` | | A `spendableCash()` read to plan from. Left out, balances are read while quotes arrive. |
| `onSigned` | | Awaited with the signed record before anything is sent, then on each bridge update. If the venue refuses the accept because its quote was just replaced, it is called with the record marked `refused`. Persist the latest record. |
| `minPayout` | The first chosen quote's payout | The least payout a later quote may pay. A retry never takes less than you were shown unless you lower it. |
| `maxAttempts` | 4 | The most accepts sent, the first included. `1` never tries another quote. |

`bestQuote()` takes the highest payout. `choose` is called again each time the listed quotes change, so it must
depend only on its argument.

Funding comes from free vault cash first, then the wallet, then a bridge of `core`. 0.05 USDC stays behind for
the bridge's gas.

### How much one Combo can stake

`readComboCash()` reads the account's balances and the signer's HyperCore cash together, and answers the largest
stake `openPosition` can fund now:

```ts
const cash = await totalis.readComboCash();
if (cash.allowance === null) throw new Error("Cash could not be read; try again");
if (stake > cash.allowance) throw new Error("Not enough cash for this stake");

await totalis.openPosition({ legs, stake, cash, core: cash.offeredCore });
```

| Field | Is |
| --- | --- |
| `vault` | Free vault cash |
| `wallet` | The wallet's HyperEVM USDC, less what pending work has reserved |
| `core` | HyperCore spot USDC less its hold |
| `coreMode` | `STANDARD`, `UNIFIED` or `PORTFOLIO_MARGIN`. A Portfolio Margin account offers no HyperCore cash. |
| `setupFee` | Whether a bridge from HyperCore still pays Hyperliquid's one-time 1 USDC setup fee |
| `offeredCore` | The HyperCore USDC to pass as `core`: `core`, less the setup fee while it is owed |
| `allowance` | `vault` + `wallet` + what a bridge can move of `offeredCore`: all of it less 0.05 USDC for the bridge's gas, and nothing when that leaves less than zero |

All amounts are atomic USDC. A field is `null` when it could not be read, and `allowance` is then `null` too:
an unread balance is never counted as zero. Pass the read as `cash` and `offeredCore` as `core` so
`openPosition` plans from the same numbers you showed.

### Why an entry did not trade

An entry can fail before it is sent, or after it is accepted.

**Before anything is sent**, while it plans the funding, `openPosition` throws `EntryError` and cancels the RFQ:

| `code` | Meaning |
| --- | --- |
| `BALANCE_UNKNOWN` | The vault balance, or a HyperCore balance the plan needs, is not current. Read it again. |
| `INSUFFICIENT_FUNDS` | Vault cash, wallet USDC and `core` (less 0.05 USDC) do not cover the stake. The message names the shortfall. |

**After it is accepted**, an operation that ends `REVERTED` or `EXPIRED_UNEXECUTED` traded nothing.
`entryFailure` names the message to show:

```ts
import { entryFailure } from "@totalis/hip4-client";

const operation = await totalis.waitForOperation(opened.operationId!);
if (operation.status !== "COMMITTED") {
  switch (entryFailure(opened.record, operation)) {
    case "INSUFFICIENT_CASH":
      show("Not enough cash to cover the stake.");
      break;
    case "CORE_MOVE_MISSED":
      show("Hyperliquid did not confirm the move from HyperCore in time. Your USDC may still be there.");
      break;
    default:
      show("The entry did not go through.");
  }
}
```

Pass the latest record, as `onSigned` last handed it to you. When the entry bridged and failed,
see [If an entry fails after its bridge](/hyperliquid/build/partner-frontend#if-an-entry-fails-after-its-bridge).

### Watch quotes yourself

To show quotes as they arrive instead of letting `openPosition` choose:

```ts
const stop = totalis.watchQuotes(rfqId, (quotes) => render(quotes));
```

The listener gets the RFQ's listed quotes, oldest first, and `[]` while the stream is down. It is called again
each time the list changes. A quote stays takeable while it is listed, so show it until it leaves the list. To
take one yourself, see [Advanced: custom signing and recovery](/hyperliquid/sdk/resume-and-retry#entry-and-cash-out).

## Settlement

When a position's markets resolve, Totalis settles it and pays the winnings into the owner's vault balance.
There is nothing to call.

## Cash out

```ts
const sale = await totalis.cashOut({ positionId });
if (sale.operationId) await totalis.waitForOperation(sale.operationId);
```

`cashOut` requests bids for the position, picks one with `bestBid()` (the highest price), has the owner, or its
[vault agent](/hyperliquid/build/partner-frontend#vault-agents), sign it, and sends the accept. If the bid was
just replaced, it takes the next one, up to `maxAttempts` (default 4). A decline or a timeout ends it, and so does
no bid within `quoteTimeoutMs`. It takes `choose` and `collectMs` like `openPosition`. `bestBid(minPrice)` takes
only bids paying at least `minPrice`.

`status` reads as for `openPosition`. `ACCEPTED` queues the sale as `operationId`.

## Deposit

```ts
const operation = await totalis.deposit({
  amount: 50_000_000n, // 50 USDC
  onStarted: (operationId) => saveDeposit(operationId),
});
console.log(operation.status); // COMMITTED when the cash is in the vault
```

`deposit` has the wallet sign a USDC authorization to the vault, which Totalis relays and pays the gas for. It
resolves with the deposit's operation once it ends. After a restart, `waitForOperation(operationId)` follows it.
The minimum and rate limits are on [Limits](/hyperliquid/limits-and-fees#deposits-and-exits).

A wallet that pays its own gas sends the deposit itself instead ([Deposit](/hyperliquid/sdk/wallets#deposit)).
An entry needs no deposit first: `openPosition` funds any vault shortfall from the wallet.

## Withdraw

```ts
await totalis.withdraw({
  destination: "0x2222222222222222222222222222222222222222",
  amount: 15_000_000n,
  onStarted: (withdrawalId) => saveWithdrawal(withdrawalId),
});
```

`withdraw` signs the `Exit` for any part of the amount the wallet is short of, plus the USDC payout, in one go.
It resolves at `PAYOUT_COMMITTED`. After a restart, `waitForWithdrawal(withdrawalId)` follows it.

A withdrawal with an unread balance throws `BalanceUnknownError` before anything is signed.

## Move cash to HyperCore

```ts
const exit = await totalis.exitToCore({ amount: 10_000_000n });
await totalis.waitForCoreExit(exit.exit_id); // resolves once HyperCore credits it
```

`exitToCore` moves free vault cash to the account's HyperCore spot balance. `returnToCore()` moves all of it,
wallet USDC included. Both are on [Move cash to HyperCore](/hyperliquid/sdk/wallets#move-cash-to-hypercore).

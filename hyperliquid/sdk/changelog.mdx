The SDK follows [semantic versioning](https://semver.org). Every release, with its additions and fixes, is in
`CHANGELOG.md` in the package. The table below is the notable releases, with the ones that need you to change
something called out.

| Version | Change |
| --- | --- |
| 0.93.1 | React Native 0.81 or later (Expo SDK 54 or later) is supported. Before it, every request failed there with `NetworkError: ... failed without a response`. Import `react-native-get-random-values` before the SDK ([Runtimes](/hyperliquid/sdk/overview#runtimes)). `createPartnerServer` now refuses to run in a React Native app, as in a browser. |
| 0.88.0 | Breaking. Cash-outs are sell-backs by the maker that backs the position: other makers no longer receive its cash-out RFQ, and there are no `TRANSFER` bids. Removes `TransferQuote`, `cashoutTransferTypedData` and `CashoutTransfer` from `totalisTypes` and `signedBy`. `CashoutBid` is `SellBackQuote`, `maker.bid` always publishes a sell-back, and `netCashout` takes only a sell-back ([Price a cash-out](/hyperliquid/guides/market-making#price-a-cash-out)). |
| 0.81.0 | Additive. `readComboCash()` answers the most one Combo can stake now (`allowance`) and the HyperCore USDC to offer as `core` (`offeredCore`), from the account's balances and the signer's HyperCore cash ([How much one Combo can stake](/hyperliquid/sdk/trading#how-much-one-combo-can-stake)). `offeredCore`, `comboAllowance`, `readCoreCash` and `hyperliquidInfo` are exported for doing the same yourself. |
| 0.77.0 | Additive. `openPosition` signs the funding first and chooses the quote last. When the quote was replaced or expired, or the maker declined it or didn't answer, it signs the best other quote paying at least `minPayout` (default: the first quote's payout) and tries again, within `refreshMs` (10 s) and `maxAttempts` (4). `prepareEntryFunding` and `signEntry({ quote, prepared })` let your own flow do the same ([Resume and retry](/hyperliquid/sdk/resume-and-retry#sign-the-funding-first)). A refused record carries `refused`. |
| 0.76.0 | Additive. Vault agents: `agent` in `createTotalis` signs accepts, cash-outs and an `Exit` back to the account in place of `signer`; `grantVaultAgent`, `revokeVaultAgent`, `vaultAgents` and `agentGrantTypedData` ([Vault agents](/hyperliquid/build/partner-frontend#vault-agents)). `createRfq` refuses two legs from one question and legs with no `chance`. |
| 0.65.2 | The first release on public npm, under Apache-2.0, and under the new name `@totalis/hip4-client`. Install with `npm install @totalis/hip4-client` and no registry setup, and change your imports from `@totalistrading/hip4-client`. Same code as 0.65.0. |
| 0.65.0 | Additive. `Operation` carries `failure_reason`, and `entryFailure(record, operation)` names why an entry did not trade: `INSUFFICIENT_CASH` or `CORE_MOVE_MISSED` ([Why an entry did not trade](/hyperliquid/sdk/trading#why-an-entry-did-not-trade)). `openPosition` returns the entry `record`. Published to GitHub Packages only. |
| 0.64.0 | Needs the venue's `accept_before`, `fund_by` and `server_time`. `sendAcceptance` posts the accept first and sends an entry's bridge only once it is `ACCEPTED`, before `fund_by`; the result's `bridge` is replaced by the `bridging` promise. `signEntry` signs everything at once and takes `cash`. Records carry `version: 2` and `bridgeState`, persisted through `onRecord`; `sendAcceptance` refuses older records. `bestQuote()` takes no argument and cuts quotes off at `accept_before`. Removes `EntryError` `QUOTE_SHORT`, `BRIDGE_LATE` and `BRIDGE_REFUSED`, and `bridged` on `ApiError` and `normalizeError`. |
| 0.63.0 | `openPosition` and `cashOut` collect quotes for `collectMs` (1 s) before choosing; pass `collectMs: 0` for the old first-quote behaviour. `signEntry` and `openPosition` without `core` throw `INSUFFICIENT_FUNDS` when the wallet is known to fall short, instead of signing an entry the venue refuses. `issueApiKey` refuses a challenge whose scopes differ from the request. |
| 0.61.0 | Adds `listApiKeys`, `revokeApiKey`, `QUOTING_BOT_SCOPES`, `COLLATERAL_SCOPES` and `examples/onboard.mjs`, for makers onboarding headless. No change to existing functions. |
| 0.60.1 | Docs only. `quote`, `bid` and `cancelQuote` can throw `ApiError` `STATE_CONFLICT` (`retry` `REFRESH`) when the venue records an acceptance while the request is on its way. Answer it in `onAcceptance`. |
| 0.60.0 | `quote` and `bid` throw `AcceptancePendingError` when an acceptance is waiting for you, and `onRfq` holds that RFQ until it is answered. `reduceCollateral` returns the job's `idempotencyKey`. |
| 0.57.0 | A resumed account stream is `live` only after its replay is applied. A withdrawal or return to HyperCore with an unread balance throws `BalanceUnknownError`, and Core exits on a deployment without them (staging) throw `ExitUnavailableError`, before anything is signed. Both used to be plain `Error`s. |
| 0.55.0 | Cash-out RFQs carry `net_stake` and `payout`. |
| 0.54.0 | Anonymous reads refuse query parameters they do not take (400 `INVALID_QUERY`). |
| 0.50.0 | `getVolumeLeaderboard` needs a signed-in session. API keys are refused. |
| 0.47.0 | A maker is one wallet. `controller()` no longer builds `setQuoteSigner`. |
| 0.45.0 | The native HyperCore withdrawal routes are gone. |

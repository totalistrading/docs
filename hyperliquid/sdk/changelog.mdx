The SDK follows [semantic versioning](https://semver.org). Every release, with its additions and fixes, is in
`CHANGELOG.md` in the package. The table below is the notable releases, with the ones that need you to change
something called out.

| Version | Change |
| --- | --- |
| 0.125.0 | Breaking. One call per action, and no quote timing. Takers: a quote stays takeable while it is listed, so `acceptBefore()`, `openPosition`'s `refreshMs` and the UI adapter's `secondsLeft` are gone. A `Chooser` is `(quotes) => quote`, with no clock argument, and `watchQuotes` listeners get only the quotes. After a refused, declined or timed-out accept, `openPosition` takes the next best quote within `quoteTimeoutMs`, up to `maxAttempts`; `cashOut` takes the next bid when its bid was just replaced, and takes `maxAttempts`. `bestBid(minPrice?)` takes no minimum life. Adds `deposit({ amount })` ([Deposit](/hyperliquid/sdk/trading#deposit)). Makers: `quote(rfq, { payout })` and `bid(rfq, { price })` send only the price and return `{ quoteId }`; `lifetimeSeconds` and `salt` are gone. The SDK confirms accepts of what it published, with `lastLook` to decline, `autoConfirm` and `onConfirmError`. The quote lease (`keepQuoteLease`, `renewQuoteLease`, `releaseQuoteLease`) and `AcceptancePendingError` are gone: `quote` and `bid` wait for a pending accept, then publish. Adds `cancelAllQuotes()`, and `close()` cancels all open quotes and returns a promise ([Make markets](/hyperliquid/sdk/making)). Quotes lead with `payout` (entry) or `price` (bid), and the signed terms move under `signing`: `quote.entry` is `quote.signing.entry`, and `quote.sell_back` is `quote.signing.sell_back`. `netCashout(bid, position)` takes the bid itself and the `position` of the position read. The accept body is only `{ taker_signature }`: a vault shortfall is drawn from the wallet's USDC approval with nothing in the accept, and the SDK signs no USDC authorization per entry ([Wallet approval](/hyperliquid/sdk/trading#wallet-approval)). `EntryFunding`, the `funding` option of `openPosition`, `signEntry` and `prepareEntryFunding`, and `PreparedEntryFunding.funding` are gone. `openPosition` and `prepareEntryFunding` sign a permit when the approval left is short; `signEntry` without `prepared` throws `WalletApprovalError` `INSUFFICIENT_APPROVAL` instead. A failed wallet-funded entry names `INSUFFICIENT_APPROVAL` or `INSUFFICIENT_WALLET_USDC` in the acceptance's `reason`. RFQs have no intents: `openPosition` drops `intent`, and `intent_id` and `intent_generation` are gone. A builder code needs no partner signature: create RFQ drops `builder_authorization_expiry` and `builder_signature`, and the code counts from an account the partner admitted or from a browser on the code's registered origin ([Builder codes](/hyperliquid/build/builder-codes#how-a-code-counts)). It credits the partner's revenue share and costs the taker nothing. `openPosition` takes `builderCode` alone; `rfqLegsInOrder` (`.../partner`) gives the leg order create RFQ requires. RFQ responses carry no clocks: the accept answers `{ status, acceptance_id, operation_id?, reason? }`, the maker's confirm answers `{ quote_id, rfq_id, status, operation_id? }` (its `deadline` comes with `QUOTE_ACCEPTED`), Get acceptance drops `deadline`, `fund_by` and `server_time` and adds `confirm_within_ms`, and `WALLET_FUNDING_UPDATED` drops `fund_by`. An entry's HyperCore bridge goes once the accept answers `ACCEPTED`, within `fundWindowMs` (4 s) of sending it. `sendAcceptance` reads nothing after the answer, and `recoverAcceptance` never sends a bridge: an unsent one is discarded. The result's `outcome` is an `AcceptOutcome`. List quotes drops `server_time`. Quotes and the maker's create quote receipt (`{ quote_id }`) carry no `accept_before`: every listed quote can be accepted. Cancel RFQ takes no `Idempotency-Key`. A cash-out RFQ names its owner `taker` and drops `legs_hash`, `leg_state`, `decision_block` and `decision_read_gas`; `maker.bid` takes an optional `legState`, and `createMaker({ chain })` adds `readCashoutPosition(rfq)` to read it with the position's ticket ([Quote](/hyperliquid/sdk/making#quote)). Adds `legsHash`, `readLegState` and `legStateReadGas`. `deposit`, `signDeposit` and `returnToCore` work with an API key, the deposit body is flat (re-sign a stored `SignedDeposit`), and a deposit over the wallet's USDC fails `INSUFFICIENT_WALLET_BALANCE`. `issueApiKey` takes `preset: "TAKER"` or `"MAKER"` in place of `scopes` ([API keys](/hyperliquid/sdk/trading#api-keys)). `GET /v1/markets` takes `combo=OPEN`, `listMarkets(filters)` pages it, and `combo.state` closes with `EVENT_PASSED` when the event starts ([Find Combo markets](/hyperliquid/sdk/trading#find-combo-markets)). Contracts 275 and 276 give each idea one name, with enum values unchanged: `reason` for why something ended, `amount` for USDC amounts (re-sign a stored `SignedDeposit` or `SignedWalletApproval`), `status` for lifecycle (with `eligibility.status` and `combo.status`), `freshness` for read freshness, `kind` for stream subscriptions, webhook events and pictures, `controller` and `signer` for the maker's wallet and a key's signer, and positions, not tickets, in partner and maker counts. HyperCore exits and run-off claims send a flat body with no `account` or `to` (re-sign a stored `SignedCoreExit`, `SignedReturnToCore` or run-off claim), a Core exit answers only `{ exit_id, status, purpose, amount, activation_fee_accepted, credit, created_at, updated_at }`, and a position read through `/v1/me` leaves out the maker-only `owner_username`, `opened_via`, `maker_pnl` and `maker_result`. |
| 0.93.1 | React Native 0.81 or later (Expo SDK 54 or later) is supported. Before it, every request failed there with `NetworkError: ... failed without a response`. Import `react-native-get-random-values` before the SDK ([Runtimes](/hyperliquid/sdk/overview#runtimes)). `createPartnerServer` now refuses to run in a React Native app, as in a browser. |
| 0.88.0 | Breaking. Cash-outs are sell-backs by the maker that backs the position: other makers no longer receive its cash-out RFQ, and there are no `TRANSFER` bids. Removes `TransferQuote`, `cashoutTransferTypedData` and `CashoutTransfer` from `totalisTypes` and `signedBy`. `CashoutBid` is `SellBackQuote`, `maker.bid` always publishes a sell-back, and `netCashout` takes only a sell-back ([Price a cash-out](/hyperliquid/guides/market-making#price-a-cash-out)). |
| 0.81.0 | Additive. `readComboCash()` answers the most one Combo can stake now (`allowance`) and the HyperCore USDC to offer as `core` (`offeredCore`), from the account's balances and the signer's HyperCore cash ([How much one Combo can stake](/hyperliquid/sdk/trading#how-much-one-combo-can-stake)). `offeredCore`, `comboAllowance`, `readCoreCash` and `hyperliquidInfo` are exported for doing the same yourself. |
| 0.77.0 | Additive. `openPosition` signs the funding first and chooses the quote last. When the quote was replaced or expired, or the maker declined it or didn't answer, it signs the best other quote paying at least `minPayout` (default: the first quote's payout) and tries again, within `refreshMs` (10 s) and `maxAttempts` (4). `prepareEntryFunding` and `signEntry({ quote, prepared })` let your own flow do the same ([Resume and retry](/hyperliquid/sdk/resume-and-retry#sign-the-funding-first)). A refused record carries `refused`. |
| 0.76.0 | Additive. Vault agents: `agent` in `createTotalis` signs accepts, cash-outs and an `Exit` back to the account in place of `signer`; `grantVaultAgent`, `revokeVaultAgent`, `vaultAgents` and `agentGrantTypedData` ([Vault agents](/hyperliquid/build/partner-frontend#vault-agents)). `createRfq` refuses two legs from one question and legs with no `chance`. |
| 0.65.2 | The first release on public npm, under Apache-2.0, and under the new name `@totalis/hip4-client`. Install with `npm install @totalis/hip4-client` and no registry setup, and change your imports from `@totalistrading/hip4-client`. Same code as 0.65.0. |
| 0.65.0 | Additive. `Operation` carries `failure_reason`, and `entryFailure(record, operation)` names why an entry did not trade: `INSUFFICIENT_CASH` or `CORE_MOVE_MISSED` ([Why an entry did not trade](/hyperliquid/sdk/trading#why-an-entry-did-not-trade)). `openPosition` returns the entry `record`. Published to GitHub Packages only. |
| 0.64.0 | Needs the venue's `accept_before`, `fund_by` and `server_time`. `sendAcceptance` posts the accept first and sends an entry's bridge only once it is `ACCEPTED`, before `fund_by`; the result's `bridge` is replaced by the `bridging` promise. `signEntry` signs everything at once and takes `cash`. Records carry `version: 2` and `bridgeState`, persisted through `onRecord`; `sendAcceptance` refuses older records. `bestQuote()` takes no argument and cuts quotes off at `accept_before`. Removes `EntryError` `QUOTE_SHORT`, `BRIDGE_LATE` and `BRIDGE_REFUSED`, and `bridged` on `ApiError` and `normalizeError`. |
| 0.63.0 | `openPosition` and `cashOut` collect quotes for `collectMs` (1 s) before choosing; pass `collectMs: 0` for the old first-quote behaviour. `signEntry` and `openPosition` without `core` throw `INSUFFICIENT_FUNDS` when the wallet is known to fall short, instead of signing an entry the venue refuses. `issueApiKey` refuses a challenge whose scopes differ from the request. |
| 0.61.0 | Adds `listApiKeys`, `revokeApiKey`, `QUOTING_BOT_SCOPES`, `COLLATERAL_SCOPES` and `examples/onboard.mjs`, for makers onboarding headless. No change to existing functions. |
| 0.60.1 | Docs only. `quote`, `bid` and `cancelQuote` can throw `ApiError` `STATE_CONFLICT` (`retry` `REFRESH`) when the venue records an acceptance while the request is on its way. Answer it in `onAcceptance`. |
| 0.60.0 | `quote` and `bid` throw `AcceptancePendingError` when an acceptance is waiting for you, and `onRfq` holds that RFQ until it is answered. `reduceCollateral` returns the job's `idempotencyKey`. |
| 0.57.0 | A resumed account stream is `live` only after its replay is applied. A withdrawal or return to HyperCore with an unread balance throws `BalanceUnknownError`, and Core exits on a deployment without them (staging) throw `ExitUnavailableError`, before anything is signed. Both used to be plain `Error`s. |
| 0.55.0 | Cash-out RFQs carry `net_stake` and `payout`. |
| 0.54.0 | Anonymous reads refuse query parameters they do not take (400 `INVALID_QUERY`). |
| 0.50.0 | `getVolumeLeaderboard` needs a signed-in session. API keys are refused. |
| 0.47.0 | A maker is one wallet. `controller()` no longer builds `setQuoteSigner`. |
| 0.45.0 | The native HyperCore withdrawal routes are gone. |

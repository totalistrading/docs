## 1. Get a key

In the [Totalis app](https://hip4.totalis.trade/account/api-keys), go to Account, then API keys,
pick the [taker scopes](/hyperliquid/authentication#scopes), and approve with your wallet. The key is shown once.
A market maker issues its keys headless instead: [Market making](/hyperliquid/guides/market-making#set-up).

```bash
export TOTALIS_API_KEY="ttk_v1_prd_..."
```

An account whose own wallet signs in on a partner's site issues its key from its wallet session instead
([Create, rotate, revoke](/hyperliquid/authentication#create-rotate-revoke)). For a frontend for your own users,
or to test on testnet first, see [Build on Totalis](/hyperliquid/build/overview).

## 2. Read

Markets need no key. Select from the current catalog instead of reusing an outcome ID from an example:

```bash
curl -fsS "https://hip4-api.totalis.trade/v1/markets?limit=200" \
  | jq '[.items[] | select(.state == "ACTIVE" and .eligibility.state == "ENABLED" and .combo.state == "OPEN")
    | {outcome_id, native_question_id, title}]'
```

`ACTIVE` alone does not mean a market admits Combo RFQs. If this page has no eligible market, follow
`next_cursor` from the original [List markets](/hyperliquid/api-reference/markets/list-markets) response,
or wait for another market to open. Never replace an empty result with a historical outcome ID.

Choose an eligible market and set its ID:

```bash
export OUTCOME_ID="<chosen-outcome-id>"
```

The list is flat: one row per market. Markets of one question share `native_question_id`.
[Get market](/hyperliquid/api-reference/markets/get-market) returns its `market`, `question` and rules.
[List questions](/hyperliquid/api-reference/markets/list-questions) (`GET /v1/discovery`) groups markets
under their question titles and lists standalone markets separately.

Your identity checks the key:

```bash
curl https://hip4-api.totalis.trade/v1/me \
  -H "Authorization: Bearer $TOTALIS_API_KEY"
```

```json
{
  "account_id": "0198a6f6-82a5-7abc-9f2a-4f0fb4374941",
  "status": "ACTIVE",
  "wallet": "0x1111111111111111111111111111111111111111"
}
```

`wallet` is your Totalis wallet. It signs your trades.

## 3. Request quotes

Subscribe to your account first, so no quote is missed:

```bash
wscat -c wss://hip4-ws.totalis.trade/v1/stream -s totalis.realtime.v2 \
  -H "Authorization: Bearer $TOTALIS_API_KEY"
> {"method":"subscribe","subscription":{"type":"account"}}
```

Wait for the account snapshot. Then create an RFQ for 5 USDC on `YES` of the market you selected.
Generate a fresh UUIDv7 for the command (Python 3.14):

```bash
export IDEMPOTENCY_KEY="$(python3.14 -c 'import uuid; print(uuid.uuid7())')"
```

The [Python HTTP example](/hyperliquid/guides/api-trading#python-http-example) includes UUIDv7 generation
for earlier Python versions. Keep this key with the exact body until the command is resolved.

```bash
curl https://hip4-api.totalis.trade/v1/rfqs \
  -H "Authorization: Bearer $TOTALIS_API_KEY" \
  -H "Idempotency-Key: $IDEMPOTENCY_KEY" \
  -H "Content-Type: application/json" \
  -d "$(jq -nc --arg id "$OUTCOME_ID" '{stake:"5000000",legs:[{outcome_id:$id,side:"YES"}]}')"
```

```json
{ "rfq_id": "01a0df4e-5e07-7a3c-8f21-d4e6b7a90c1a" }
```

Quotes arrive on the socket as `QUOTE_CREATED`, each with a `payout`. Creating an RFQ spends no stake.
There may be no quote; a quote request is not a guaranteed fill.

## 4. Accept

Your API key authenticates the request. It does not sign the trade: your account wallet signs the exact
quote. Accept it before its `accept_before` and follow the operation until `COMMITTED`:
[Trading](/hyperliquid/guides/trading#accept).

For an HTTP bot with executable signing and recovery, use [API trading](/hyperliquid/guides/api-trading).

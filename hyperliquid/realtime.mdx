Totalis pushes every change to your account or maker over one WebSocket. The SDK flows run on it:
they wait for events and read over HTTP only after a reconnect or when an event says something
changed. Build the same way. Use the HTTP reads to recover, not to poll.

| | Value |
| --- | --- |
| URL | `wss://hip4-api.totalis.trade/v1/stream` (staging: `wss://hip4-api-staging.totalis.trade/v1/stream`) |
| Subprotocol | `totalis.realtime.v1` |
| Credential | Servers send `Authorization: Bearer <key>`. Browsers, which cannot set headers, add a second subprotocol `auth.<base64url of the key>`. |
| Topic | `ACCOUNT` for a personal key (needs `account:stream`). `MAKER` for a maker key (needs `rfq:read`, `quote:read`, or `vault:read`). |

Each key receives only the frames its scopes allow. The frame classes per scope are on
[Open realtime stream](/hyperliquid/api-reference/realtime/open-realtime-stream).

## With the SDK

```ts
import { TotalisStream } from "@totalistrading/hip4-client/realtime";

const stream = new TotalisStream({
  environment: "production",
  accessToken: process.env.TOTALIS_API_KEY!,
  topic: "ACCOUNT",
});
stream.on("status", (status) => console.log(status)); // connecting, live, disconnected, closed
stream.on("snapshot", (snapshot) => console.log("replace local state", snapshot.cursor));
stream.on("reset", () => console.log("local state is void; a snapshot follows"));
stream.on("event", (event) => {
  if (event.event_type === "EXECUTION_REPORT") console.log(event.payload.operation_id, event.payload.state);
  if (event.event_type === "BALANCE_CHANGED") console.log("re-read GET /v1/me/balances");
});
stream.start();
```

`TotalisStream` sends the hello, applies the snapshot or replay, drops duplicate and out-of-order
events, and reconnects with jittered backoff from the last applied cursor. `status` is `live` only
while subscribed and caught up, so treat anything you built from the stream as stale otherwise.
`stream.cursor` is the last applied cursor. Pass it back as `cursor` to resume after a restart.
`createTotalis` and `createMaker` each hold one of these as `stream`.

## The protocol

<Steps>
  <Step title="Say hello">
    The first frame you send names exactly one subscription, whose topic must match your key:

    ```json
    {
      "type": "session.hello",
      "schema_version": 1,
      "client_instance_id": "01a0df4e-5c11-7d2a-9b3c-4d5e6f7a8b9c",
      "subscriptions": [{ "topic": "ACCOUNT" }]
    }
    ```

    A maker adds `"rfq_details": true` to receive each entry RFQ alongside its `ENTRY_RFQ_OPENED`
    event. Add `"publication_freshness": true` for faster heartbeats and publication checkpoints.
  </Step>
  <Step title="Read the ready frame">
    ```json
    {
      "type": "session.ready",
      "connection_id": "01a0df4e-5c12-7e3b-8c4d-5e6f7a8b9c0d",
      "server_time": "2026-09-26T20:00:05Z",
      "heartbeat_interval_ms": 15000,
      "max_frame_bytes": 262144,
      "topic": "ACCOUNT",
      "resume": "SNAPSHOT",
      "cursor": { "stream_id": "0199a1c2-3b4d-7e5f-8a6b-1c2d3e4f5a60", "generation_id": "0199a1c2-3b4d-7e5f-8a6b-1c2d3e4f5a61", "sequence": "184243" }
    }
    ```

    Events follow strictly after `cursor`. The server sends a heartbeat on `heartbeat_interval_ms`
    when the stream is otherwise idle.
  </Step>
  <Step title="Apply the snapshot">
    Without a resume cursor, a `stream.snapshot` frame follows with your current live state (for a maker: open
    RFQs, quotes, confirmation requests, operations) and its cursor. Replace your local state with it.
    A class truncated for size is named in `continuations` with the HTTP list that holds the rest.
    Balances, positions, and maker capital are not in the snapshot. Read them over HTTP on connect.
  </Step>
  <Step title="Apply events">
    Each `stream.event` frame carries one event:

    ```json
    {
      "type": "stream.event",
      "event": {
        "schema_version": 1,
        "stream": { "stream_id": "0199a1c2-3b4d-7e5f-8a6b-1c2d3e4f5a60", "generation_id": "0199a1c2-3b4d-7e5f-8a6b-1c2d3e4f5a61", "sequence": "184244" },
        "event_id": "0199a1c9-2c33-7e5f-9a42-7d9eafbc0005",
        "event_type": "EXECUTION_REPORT",
        "resource_kind": "OPERATION",
        "resource_id": "0x9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a",
        "occurred_at": "2026-09-26T20:00:06.114Z",
        "payload": {
          "operation_id": "0x9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a9a",
          "state": "COMMITTED",
          "transaction_hash": "0xa7a7a7a7a7a7a7a7a7a7a7a7a7a7a7a7a7a7a7a7a7a7a7a7a7a7a7a7a7a7a7a7",
          "updated_at": "2026-09-26T20:00:06.114Z"
        }
      }
    }
    ```

    Delivery is at least once. Skip an event whose `event_id` you have seen or whose `sequence` is not
    above your cursor. Persist `event.stream` as your cursor only after you have applied the event.
  </Step>
</Steps>

## Events

Many events are doorbells: they say which resource changed, and you re-read it over HTTP.

| Event | Do |
| --- | --- |
| `BOOK_QUOTES_CHANGED` | Re-read the book of `payload.rfq_id`. The event is a signal, not a quote. |
| `EXECUTION_REPORT`, `WITHDRAWAL_REPORT` | Operation progress: `operation_id`, `state`, `transaction_hash`. |
| `BALANCE_CHANGED`, `WALLET_BALANCE_CHANGED` | Re-read [Get balances](/hyperliquid/api-reference/account/get-balances). |
| `TOTALIS_WITHDRAWAL_CONTINUATION_UPDATED` | Re-read the withdrawal. See [Funding](/hyperliquid/funding#withdraw-to-any-address). |
| `TICKET_ACCEPTED`, `TICKET_OWNER_CHANGED`, `TICKET_SETTLED`, `TICKET_CLOSED`, `TICKET_UPDATED` | Re-read the position. |
| `ENTRY_RFQ_OPENED`, `CASHOUT_RFQ_OPENED` | Price the RFQ. See [Market makers](/hyperliquid/market-makers#receiving-rfqs). |
| `RFQ_SELECTION_DURABLE`, `RFQ_CANCELLED`, `RFQ_CLOSED` | The RFQ was taken, cancelled, or closed. Stop quoting it. |
| `CONFIRMATION_REQUESTED` | A taker selected your quote or bid. Answer before its `deadline`. |
| `ENTRY_QUOTE_DISPLAYED`, `CASHOUT_BID_DISPLAYED`, `ENTRY_QUOTE_REMOVED_FROM_DISPLAY`, `CASHOUT_BID_REMOVED_FROM_DISPLAY` | A quote or bid entered or left the book. |
| `MAKER_VAULT_UPDATED` | Re-read [Get maker capital](/hyperliquid/api-reference/maker-reads/get-maker-capital). |
| `COLLATERAL_REDUCTION_UPDATED` | Re-read the collateral reduction job. |

Handle event types you do not recognize by ignoring them. New types are added without notice.

## Resume after a disconnect

Send your last applied cursor in the subscription (this needs `replay:read`):

```json
{
  "type": "session.hello",
  "schema_version": 1,
  "client_instance_id": "01a0df4e-5c11-7d2a-9b3c-4d5e6f7a8b9c",
  "subscriptions": [{ "topic": "MAKER", "cursor": { "stream_id": "0199a1c2-3b4d-7e5f-8a6b-1c2d3e4f5a60", "generation_id": "0199a1c2-3b4d-7e5f-8a6b-1c2d3e4f5a61", "sequence": "184244" } }]
}
```

| `resume` in `session.ready` | Do |
| --- | --- |
| `REPLAY` | Missed events follow. Apply them in order. |
| `SNAPSHOT` | No cursor was sent. Replace your local state with the snapshot that follows. |
| `RESET` | The cursor cannot be replayed. Discard your local state and apply the snapshot that follows. |

Makers can also replay over HTTP with [List maker events](/hyperliquid/api-reference/realtime/list-maker-events):
page with `cursor` until `has_more` is `false`, then subscribe from `next_cursor`. A cursor that can
no longer be replayed returns `CURSOR_RESET`: take a fresh snapshot. The replay window is on
[Limits and timing](/hyperliquid/conventions#limits-and-timing).

## Reconnects and close reasons

The server may send `connection.drain` with `retry_after_ms` before it closes a connection for
maintenance. Reconnect after that delay and resume from your cursor. Any other close carries a reason
from the [error registry](/hyperliquid/errors), and its `retry` value says what to do:

| `retry` | Do |
| --- | --- |
| `BACKOFF` | Reconnect with backoff and resume from your cursor. |
| `REFRESH` | Reconnect without a cursor and apply the fresh snapshot. |
| `NEVER` | Stop. The credential or subscription is not allowed, for example `SUBSCRIPTION_DENIED` or `AUTHORIZATION_REVOKED`. |

Totalis posts events about your users to one HTTPS URL on your server: new accounts, positions opened, claimed,
sold back and settled, and operation and withdrawal updates. You stop polling for them. Delivery follows
[Standard Webhooks](https://www.standardwebhooks.com/), so any Standard Webhooks library verifies it.

## Set up

Email [founders@totalis.trade](mailto:founders@totalis.trade) with your HTTPS URL and the environment
(production or [staging](/hyperliquid/build/staging)). Totalis registers it and sends you a signing secret once:
`whsec_` followed by 32 random bytes in base64. Store it like a password.

| Change | How |
| --- | --- |
| New URL | Email us. A new URL comes with a new secret; the old secret stops signing. |
| Test delivery | Ask us for a `ping`. |
| Stop | Email us. Undelivered events are dropped. |

The URL must be `https://` on a public address, with no credentials or fragment. You get events Totalis records
while your webhook is set. Nothing from before is replayed, though the first events can be from shortly before.

## Events

Each event is one `POST` with a JSON body:

```json
{
  "id": "fill_48213345_7",
  "type": "position.opened",
  "created_at": "2026-11-12T15:04:05Z",
  "data": {}
}
```

| Field | Value |
| --- | --- |
| `id` | Stable per event, and the same on every retry. Dedupe on it. |
| `type` | One of the types below |
| `created_at` | When it happened: the block time for a fill or settlement, otherwise when Totalis recorded it. RFC 3339, UTC. |
| `data` | Depends on `type` |

| `type` | When | `data` |
| --- | --- | --- |
| `account.created` | A wallet you admitted created its Totalis account | `wallet`, `created_at` |
| `position.opened` | A position opened with one of your [builder codes](/hyperliquid/build/builder-codes) | A fill, `kind` `ACCEPT` |
| `position.claimed` | Such a position was claimed | A fill, `kind` `CLAIM` |
| `position.sold_back` | Such a position was cashed out to the vault | A fill, `kind` `CASH_OUT` |
| `position.settled` | Such a position settled. A win is claimed later; a loss closes at once. | A settlement |
| `operation.updated` | An operation of an account you admitted changed status | `wallet`, `occurred_at`, and `payload`: the stream's [`OPERATION_UPDATED`](/hyperliquid/api-reference/websocket/account#event) payload |
| `withdrawal.updated` | A withdrawal of such an account changed | `wallet`, `occurred_at`, and `payload`: the stream's [`WITHDRAWAL_UPDATED`](/hyperliquid/api-reference/websocket/account#event) payload |
| `ping` | Totalis tested your webhook | `{}` |

A position stays yours after it changes hands. New event types and new `data` fields can be added: ignore what you
do not recognise.

### Fill

```json
{
  "kind": "ACCEPT",
  "wallet": "0x3f5ce5fbfe3e9af3971dd833d26ba9b5c936f0be",
  "position_id": "0x6f1d2c0e9b4a7d3f8e2b1c5a9d0e4f7b3a6c8d1e2f5a9b0c4d7e1f3a5b8c2d6e",
  "legs": [{ "outcome_id": "1209", "side": "YES" }],
  "amount": "5000000",
  "fee": "75000",
  "stake": "4925000",
  "payout": "12500000",
  "share_bps": 2000,
  "time": "2026-11-12T15:04:05Z",
  "block_number": 48213345,
  "log_index": 7,
  "transaction_hash": "0x9a1e5c7d3b2f4e6a8c0d1f3b5a7e9c2d4f6b8a0e1c3d5f7a9b2e4c6d8f0a1b3c"
}
```

| Field | Value |
| --- | --- |
| `kind` | `ACCEPT` (the position opened), `CLAIM` or `CASH_OUT` |
| `wallet` | The wallet that acted, lowercase hex |
| `position_id`, `legs` | The position and its legs |
| `amount` | The gross stake, claim or cash-out price |
| `fee` | The fee this fill paid |
| `stake`, `payout` | The position's net stake and what it pays if every leg wins, fixed when it opened. On every fill, so a claim reads without its opening. |
| `share_bps` | Your [revenue share](/hyperliquid/build/builder-codes#reports-and-payouts) on the fill's day, in basis points. `null` before your first terms. |
| `time`, `block_number`, `log_index`, `transaction_hash` | Where it happened on HyperEVM |

### Settlement

| Field | Value |
| --- | --- |
| `position_id`, `legs` | The position and its legs |
| `owner` | The wallet it settled for |
| `settlement_kind` | `WIN`, `LOSS`, `PARTIAL` or `EARLY_LOST` |
| `stake`, `payout` | As on a fill |
| `share_bps` | As on a fill |
| `time`, `block_number`, `log_index`, `transaction_hash` | Where it settled on HyperEVM |

Amounts are atomic USDC decimal strings, 6 decimals: `"1500000"` is 1.50 USDC. Wallets are lowercase hex.

## Verify

Every request carries three headers:

| Header | Value |
| --- | --- |
| `webhook-id` | The event's `id` |
| `webhook-timestamp` | Unix seconds when this attempt was signed |
| `webhook-signature` | `v1,` and the base64 HMAC-SHA256 of `{webhook-id}.{webhook-timestamp}.{body}` |

The HMAC key is the base64-decoded part of your secret after `whsec_`. Verify against the raw body bytes before you
parse them, compare in constant time, and refuse a timestamp more than a few minutes from your clock. The header
can list several space-separated signatures: accept the request if any one matches.

```ts
import { Webhook } from "standardwebhooks";

const webhook = new Webhook(process.env.TOTALIS_WEBHOOK_SECRET);

// rawBody is the request body exactly as received, before JSON parsing.
const event = webhook.verify(rawBody, {
  "webhook-id": headers["webhook-id"],
  "webhook-timestamp": headers["webhook-timestamp"],
  "webhook-signature": headers["webhook-signature"],
});
```

## Delivery

| Rule | Detail |
| --- | --- |
| Delivered | Any `2xx` within the [timeout](/hyperliquid/limits-and-fees#partner-webhooks) |
| Failed | Any other status, a redirect, or no answer in time. Redirects are not followed. |
| Retried | On the [retry schedule](/hyperliquid/limits-and-fees#partner-webhooks), then dropped |
| Duplicates | Possible. A repeat has the same `id`. |
| Order | None. Events of one position or account can arrive out of order: order them by `created_at`, or by block and log. |

Answer `2xx` as soon as you have stored the event, and do the work after. A slow handler times out and is retried.

## Your users' balances

Webhooks cover what happens through Totalis. A USDC transfer into or out of a user's wallet outside Totalis sends no
event. For a live view of one account, use the [account stream](/hyperliquid/guides/realtime), which also sends
`WALLET_BALANCE_CHANGED` and `VAULT_BALANCE_CHANGED`.

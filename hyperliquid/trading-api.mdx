Trading takes a handful of calls. Each step below names the route and the
[SDK](/hyperliquid/sdk) call that sends it. The SDK makes every call in a step for you, including
the retries and the recovery reads. Every route takes your API key as
`Authorization: Bearer <key>` on `https://hip4-api.totalis.trade`.

## Taker

| Step | Route | SDK |
| --- | --- | --- |
| 1. Get an API key | In the [Totalis app](https://totalis-hip4.vercel.app/account/api-keys), with the [taker bot scopes](/hyperliquid/authentication#recommended-scope-sets) | None |
| 2. Read the vault | [`GET /v1/vault`](/hyperliquid/api-reference/vault/get-vault-release) | Read by every flow, as `totalis.release()` |
| 3. Open the stream | [`GET /v1/stream`](/hyperliquid/api-reference/realtime/open-realtime-stream), topic `ACCOUNT` | `totalis.stream`, opened on first use |
| 4. Request quotes | [`POST /v1/rfqs`](/hyperliquid/api-reference/rfqs-and-quotes/create-rfq) | `totalis.placeBet({ legs, stake })` |
| 5. Accept a quote | [`POST /v1/rfqs/{rfq_id}/attempts/{attempt_id}`](/hyperliquid/api-reference/rfqs-and-quotes/accept-quote). A vault shortfall is funded from your wallet in the same call. | `placeBet` |
| 6. Cancel an RFQ you will not take | [`POST /v1/rfqs/{rfq_id}/cancel`](/hyperliquid/api-reference/rfqs-and-quotes/cancel-rfq) | `placeBet` and `cashOut`, when no acceptable offer arrives in time |
| 7. Cash out early | Steps 4 and 5 with a cash-out RFQ: `{ "kind": "CASHOUT", "ticket_id": "0x..." }` | `totalis.cashOut({ ticketId })` |
| 8. Withdraw to any address | [`POST /v1/withdrawals`](/hyperliquid/api-reference/funds/withdraw-to-an-external-address), one signed request | `totalis.withdraw({ destination, amount })` |

There is no deposit step and no claim step. The accept funds any vault shortfall from your wallet,
and Totalis settles and claims every decided ticket into your vault balance. The quotes for an RFQ
arrive on the stream, not from a route: the snapshot's `book_quotes`, then `BOOK_QUOTE_PUBLISHED`
and `BOOK_QUOTE_REMOVED` events. The accept returns the final result, and a withdrawal reports each
change as `WITHDRAWAL_UPDATED`, so there is nothing to poll. [Trading](/hyperliquid/trading) and
[Funding](/hyperliquid/funding) walk through each step.

```ts
import { createTotalis } from "@totalistrading/hip4-client";
import { privateKeyToAccount } from "viem/accounts";

const totalis = createTotalis({
  environment: "production",
  accessToken: process.env.TOTALIS_API_KEY!,
  signer: privateKeyToAccount(process.env.TOTALIS_WALLET_KEY as `0x${string}`),
});

const bet = await totalis.placeBet({ legs: [{ outcome_id: 1209, side: 0 }], stake: 25_000_000n }); // steps 2 to 6
if (bet.state === "COMMITTED") await totalis.waitForOperation(bet.operationId!); // the ticket is on-chain

const cashout = await totalis.cashOut({ ticketId: bet.quoteDigest }); // step 7, while the ticket is open

await totalis.withdraw({ destination: "0x2222222222222222222222222222222222222222", amount: 10_000_000n }); // step 8
```

## Maker

| Step | Route | SDK |
| --- | --- | --- |
| 1. Set up the maker and a maker key | In the [Totalis app](https://totalis-hip4.vercel.app/mm). See [Market makers](/hyperliquid/market-makers#1-set-up-your-maker-in-the-app). | None |
| 2. Read your capital | [`GET /v1/makers/{maker_id}/capital`](/hyperliquid/api-reference/maker/get-maker-capital) | `maker.client.GET("/v1/makers/{maker_id}/capital", ...)` |
| 3. Open the stream | [`GET /v1/stream`](/hyperliquid/api-reference/realtime/open-realtime-stream), topic `MAKER`: a snapshot of open RFQs, confirmation requests, and operations, then events. It is also how you resume: pass your last cursor. | `maker.onRfq(handler)` delivers each open RFQ once |
| 4. Publish a quote or a bid | [`POST /v1/rfqs/{rfq_id}/book-quotes`](/hyperliquid/api-reference/rfqs-and-quotes/publish-quote) | `maker.quote(rfq, { payout })` on an entry RFQ, `maker.bid(rfq, { price })` on a cash-out RFQ |
| 5. Withdraw it | [`DELETE /v1/rfqs/{rfq_id}/book-quotes/{quote_digest}`](/hyperliquid/api-reference/rfqs-and-quotes/withdraw-quote) | `maker.withdraw(rfqId, quoteDigest)` |
| 6. Confirm a fill | [`POST /v1/rfqs/{rfq_id}/attempts/{attempt_id}/confirmation`](/hyperliquid/api-reference/rfqs-and-quotes/confirm-attempt), on each `CONFIRMATION_REQUESTED` | `maker.onConfirmation(handler)` |

Publishing needs no signature. You sign only when a taker selects your offer and the confirmation
request arrives. [Market makers](/hyperliquid/market-makers) walks through each step.

```ts
import { createMaker } from "@totalistrading/hip4-client/maker";
import { privateKeyToAccount } from "viem/accounts";

const maker = createMaker({
  environment: "production",
  apiKey: process.env.TOTALIS_MAKER_KEY!,
  makerId: process.env.TOTALIS_MAKER_ID!,
  signer: privateKeyToAccount(process.env.QUOTE_SIGNER_KEY as `0x${string}`),
});

maker.onRfq(async (rfq) => {
  if (rfq.kind === "ENTRY") await maker.quote(rfq, { payout: (BigInt(rfq.stake_amount) * 18n) / 10n }); // step 4
  else await maker.bid(rfq, { price: 18_000_000n });
});
maker.onConfirmation(() => "CONFIRM"); // step 6
```

The payout and price above are placeholders. Price from your own market data.

## Everything else

The API reference keeps every other route under **Reference**. None of it is needed to trade.

| Group | Holds | When you need it |
| --- | --- | --- |
| Market data | Market list, market detail (with its question, metadata, recurring round, and 24h stats), and price history | To find `outcome_id`s. No key needed. |
| Account | Identity, balances, positions, activity. A maker key reads its maker's positions and activity here too. | To show a portfolio or a maker dashboard. |
| Operations | Your account's on-chain operations, personal or maker | `waitForOperation` reads them for you. |
| Maker | Collateral reduction, and the relay for transactions your maker pays gas for | To release collateral. |
| Recovery | RFQ, book, attempt, withdrawal, operation, and confirmation reads | The SDK does this for you after a reconnect, a truncated snapshot, or a lost response. |

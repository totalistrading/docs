Trading takes a handful of calls. Each step below names the route and the
[SDK](/hyperliquid/sdk) call that sends it. The SDK makes every call in a step for you, including
the retries and the recovery reads. Every route takes your API key as
`Authorization: Bearer <key>` on `https://hip4-api.totalis.trade`.

## Taker

| Step | Route | SDK |
| --- | --- | --- |
| 1. Get an API key | In the [Totalis app](https://totalis-hip4.vercel.app/account/api-keys), with the [taker bot scopes](/hyperliquid/authentication#recommended-scope-sets) | None |
| 2. Read the vault | [`GET /v1/vault`](/hyperliquid/api-reference/vault/get-vault-release) | Read by every flow, as `totalis.release()` |
| 3. Deposit | [`POST /v1/deposits`](/hyperliquid/api-reference/funds-and-tickets/deposit) | `totalis.deposit({ amount })`. Optional: `placeBet` funds a vault shortfall in its accept. |
| 4. Open the stream | [`GET /v1/stream`](/hyperliquid/api-reference/realtime/open-realtime-stream), topic `ACCOUNT` | `totalis.stream`, opened on first use |
| 5. Request quotes | [`POST /v1/rfqs`](/hyperliquid/api-reference/rfqs-and-quotes/create-rfq) | `totalis.placeBet({ legs, stake })` |
| 6. Accept a quote | [`POST /v1/rfqs/{rfq_id}/attempts/{attempt_id}`](/hyperliquid/api-reference/rfqs-and-quotes/accept-quote) | `placeBet` |
| 7. Cancel an RFQ you will not take | [`POST /v1/rfqs/{rfq_id}/cancel`](/hyperliquid/api-reference/rfqs-and-quotes/cancel-rfq) | `placeBet` and `cashOut`, when no acceptable offer arrives in time |
| 8. Cash out early | Steps 5 and 6 with a cash-out RFQ: `{ "kind": "CASHOUT", "ticket_id": "0x..." }` | `totalis.cashOut({ ticketId })` |
| 9. Claim winnings | [`POST /v1/tickets/{ticket_id}/claims`](/hyperliquid/api-reference/funds-and-tickets/claim-ticket) | `totalis.claimTicket(ticketId)`. Optional: Totalis claims settled tickets on its own. |
| 10. Withdraw | See [Withdraw](#withdraw) | `totalis.withdraw({ destination, amount })` |

The quotes for an RFQ arrive on the stream, not from a route: the snapshot's `book_quotes`, then
`BOOK_QUOTE_PUBLISHED` and `BOOK_QUOTE_REMOVED` events. The accept returns the final result, so
there is nothing to poll. [Trading](/hyperliquid/trading) walks through each step.

```ts
import { createTotalis } from "@totalistrading/hip4-client";
import { privateKeyToAccount } from "viem/accounts";

const totalis = createTotalis({
  environment: "production",
  accessToken: process.env.TOTALIS_API_KEY!,
  signer: privateKeyToAccount(process.env.TOTALIS_WALLET_KEY as `0x${string}`),
});

const bet = await totalis.placeBet({ legs: [{ outcome_id: 1209, side: 0 }], stake: 25_000_000n }); // steps 2 to 7
if (bet.state === "COMMITTED") await totalis.waitForOperation(bet.operationId!); // the ticket is on-chain

const cashout = await totalis.cashOut({ ticketId: bet.quoteDigest }); // step 8, while the ticket is open
```

### Withdraw

Withdrawing to an external address takes four calls today. `totalis.withdraw` makes all of them.
[Funding](/hyperliquid/funding#withdraw-to-any-address) has the details.

| Call | Route |
| --- | --- |
| Start the withdrawal | [`POST /v1/totalis-withdrawals`](/hyperliquid/api-reference/funds-and-tickets/create-totalis-withdrawal) |
| Read it after a reconnect | [`GET /v1/totalis-withdrawals/{continuation_id}`](/hyperliquid/api-reference/funds-and-tickets/get-totalis-withdrawal) |
| Claim the payout | [`POST /v1/totalis-withdrawals/{continuation_id}/payout-claim`](/hyperliquid/api-reference/funds-and-tickets/claim-totalis-withdrawal-payout) |
| Submit the signed payout | [`POST /v1/totalis-withdrawals/{continuation_id}/payout-submission`](/hyperliquid/api-reference/funds-and-tickets/record-totalis-payout-submission) |

## Maker

| Step | Route | SDK |
| --- | --- | --- |
| 1. Set up the maker and a maker key | In the [Totalis app](https://totalis-hip4.vercel.app/mm). See [Market makers](/hyperliquid/market-makers#1-set-up-your-maker-in-the-app). | None |
| 2. Read your capital | [`GET /v1/makers/{maker_id}/capital`](/hyperliquid/api-reference/maker-reads/get-maker-capital) | `maker.client.GET("/v1/makers/{maker_id}/capital", ...)` |
| 3. Open the stream | [`GET /v1/stream`](/hyperliquid/api-reference/realtime/open-realtime-stream), topic `MAKER`: a snapshot of open RFQs, quotes, and confirmation requests, then events | `maker.onRfq(handler)` delivers each open RFQ once |
| 4. Publish a quote or a bid | [`POST /v1/rfqs/{rfq_id}/book-quotes`](/hyperliquid/api-reference/rfqs-and-quotes/publish-quote) | `maker.quote(rfq, { payout })` on an entry RFQ, `maker.bid(rfq, { price })` on a cash-out RFQ |
| 5. Withdraw it | [`DELETE /v1/rfqs/{rfq_id}/book-quotes/{quote_digest}`](/hyperliquid/api-reference/rfqs-and-quotes/withdraw-quote) | `maker.withdraw(rfqId, quoteDigest)` |
| 6. Confirm a fill | [`POST /v1/rfqs/{rfq_id}/attempts/{attempt_id}/confirmation`](/hyperliquid/api-reference/rfqs-and-quotes/confirm-attempt), on each `CONFIRMATION_REQUESTED` | `maker.onConfirmation(handler)` |

Publishing needs no signature. You sign only when a taker selects your offer and the confirmation
request arrives. [Market makers](/hyperliquid/market-makers) walks through each step.

```ts
import { createMaker } from "@totalistrading/hip4-client/maker";
import { privateKeyToAccount } from "viem/accounts";

const maker = createMaker({
  environment: "production",
  apiKey: process.env.TOTALIS_MAKER_KEY!,
  makerId: process.env.TOTALIS_MAKER_ID!,
  signer: privateKeyToAccount(process.env.QUOTE_SIGNER_KEY as `0x${string}`),
});

maker.onRfq(async (rfq) => {
  if (rfq.kind === "ENTRY") await maker.quote(rfq, { payout: (BigInt(rfq.stake_amount) * 18n) / 10n }); // step 4
  else await maker.bid(rfq, { price: 18_000_000n });
});
maker.onConfirmation(() => "CONFIRM"); // step 6
```

The payout and price above are placeholders. Price from your own market data.

## Everything else

The API reference keeps every other route under **Reference**. None of it is needed to trade.

| Group | Holds | When you need it |
| --- | --- | --- |
| Market data | Markets, questions, search, history, stats | To find `outcome_id`s. No key needed. |
| Account | Identity, balances, positions, activity | To show a portfolio. |
| Operations | Your on-chain operations | `waitForOperation` reads them for you. |
| Funds and tickets | Direct vault withdrawal, ticket transfer, settlement | Rarely. Totalis settles tickets on its own. |
| Maker | Positions, activity, performance, offers, collateral reduction | For a maker dashboard. |
| HyperCore | Your HyperCore portfolio and history | To show HyperCore balances. |
| Recovery | RFQ, book, attempt, and confirmation reads | The SDK does this for you after a reconnect, a truncated snapshot, or a lost response. |

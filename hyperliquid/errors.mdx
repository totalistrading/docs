Every HTTP error, on every route, uses one envelope:

```json
{
  "error": {
    "code": "INVALID_REQUEST",
    "message": "The stake must be a positive integer.",
    "retry": "NEVER",
    "request_id": "0198f0a2-5c1e-7b3a-9f10-2d4c6e8a0b12",
    "field_violations": [
      { "field": "/stake_amount", "code": "INVALID" }
    ]
  }
}
```

| Field | Use it to |
| --- | --- |
| `code` | Branch in code. Codes are stable. |
| `message` | Log or display. The wording may change without notice, so never branch on it. |
| `retry` | Decide what to do next. See the table below. |
| `request_id` | Quote to support when reporting a problem. It is this request's own ID, the same UUIDv7 as the `X-Request-ID` response header. |
| `field_violations` | Find the invalid inputs. Always present. Each names a JSON pointer into the body (`/stake_amount`), or into the query parameters for a request without a body (`/limit`), with a `code` of `REQUIRED`, `INVALID`, or `UNEXPECTED`. |

## Retry

Each code has exactly one `retry` value:

| `retry` | What to do |
| --- | --- |
| `NEVER` | Stop. The same request cannot succeed. |
| `BACKOFF` | Resend the same request, with the same `Idempotency-Key` and body, after the `Retry-After` header (seconds). Every `BACKOFF` response carries it. |
| `REFRESH` | Re-read the state the request depends on (the RFQ, the book, the balance, the cursor), then send a new request with a new `Idempotency-Key`. |

The SDK resends `BACKOFF` errors for you and throws `ApiError` with the same fields for everything
else. See [TypeScript SDK](/hyperliquid/sdk#retries-and-errors).

## Statuses

| HTTP | Meaning |
| ---: | --- |
| `400` | Malformed request: body, path, header, or query validation. |
| `401` | Missing, invalid, expired, or revoked credential. |
| `403` | Valid credential without the scope or permission required. |
| `404` | The resource does not exist, or is not visible to this credential. |
| `409` | Conflict with current state, including idempotency key reuse. |
| `422` | Well formed, but a business or signature rule rejects it. |
| `429` | Quota or capacity limit. Always `BACKOFF` with `Retry-After`. |
| `503` | A required dependency is unavailable or stale, and the request failed closed. Always `BACKOFF` with `Retry-After`. |

Realtime stream closes use the same registry: the close reason is the code, with a fixed close
status. See [Realtime](/hyperliquid/realtime#reconnects-and-close-reasons).

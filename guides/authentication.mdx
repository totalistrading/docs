The Totalis API accepts two authentication schemes.

| Scheme | Used by | How it is sent |
| --- | --- | --- |
| API key | Programmatic clients: bots, scripts, server-side integrations | `X-API-Key` header on REST and SSE. In the auth message on the WebSocket. |
| Privy JWT | The web dashboard | `Authorization: Bearer <jwt>` |

Either scheme works on every authenticated endpoint, with one exception. Creating a new API key
(`POST /v1/api-keys`) requires a Privy JWT, or an API key that already holds the `keys:manage`
scope.

## Getting your API key

<Steps>
  <Step title="Log in">
    Open [app.totalis.trade](https://app.totalis.trade) and go to your account settings.
  </Step>
  <Step title="Create the key">
    Name it and choose its scopes. Grant only what this integration needs.
  </Step>
  <Step title="Copy it immediately">
    The full key is returned exactly once, in `data.key`.
  </Step>
</Steps>

<Warning>
The full API key is displayed only at creation. Store it in a secret manager before you close the
dialog. It cannot be retrieved later, only revoked and replaced.
</Warning>

Keys match `api_(live|test)_[A-Za-z0-9_-]{28,36}`. Live keys start `api_live_`, test environment keys
start `api_test_`.

## Using your API key

```bash
curl https://api.totalis.trade/v1/portfolio \
  -H "X-API-Key: $TOTALIS_API_KEY"
```

On the WebSocket, authenticate after connecting:

```json
{ "type": "auth", "api_key": "<your-api-key>" }
```

A credential that does not start with `api_` is rejected with `403` and reason
`wrong_api_key_type`, and the response carries a hint about the expected format. A well formed but
invalid or revoked key gets `401`. See [Errors](/api-reference/errors).

## Scopes

Every key carries the set of scopes you selected at creation. A request to an endpoint whose scope
the key lacks is rejected with `403` and reason `insufficient_scope`.

| Scope | Grants | Risk |
| --- | --- | --- |
| `account:read` | View account profile and username. | low |
| `markets:read` | Browse markets, including each market's `exclusion_keys`. | low |
| `positions:read` | View quote requests, portfolio, stats, and P&L. | low |
| `balances:read` | View wallet and vault balances and delegation status. | low |
| `funds:deposit` | Move USDC into the vault. | low |
| `trading:write` | Create, modify, commit, and cancel quote requests. Places parlays. | medium |
| `account:write` | Change username and profile settings. | medium |
| `mm:quote` | Read quote requests and submit or confirm quotes as a market maker. | medium |
| `funds:withdraw` | Move USDC out of the vault or wallet to any address. | **high** |
| `tx:sign` | Submit arbitrary signed Solana transactions. | **high** |
| `keys:manage` | Create, list, and revoke API keys. | **high** |

<Warning>
The three high risk scopes each let a leaked key take everything. `funds:withdraw` sends USDC to any
address. `tx:sign` submits arbitrary transactions. `keys:manage` mints more keys, including ones
that outlive your revocation of the original. Issue them only to keys that genuinely need them, and
never to a key that also lives in a browser or a CI log.
</Warning>

Pick scopes by integration shape:

| Integration | Scopes |
| --- | --- |
| Dashboard or reconciliation, read only | `account:read`, `positions:read`, `balances:read` |
| Trading bot | the read scopes, plus `trading:write`, plus `funds:deposit` if it tops up the vault |
| Market maker | the read scopes, plus `mm:quote` |

## Managing keys

| Action | Endpoint |
| --- | --- |
| List keys | [`GET /v1/api-keys`](/api-reference/user/list-api-keys) |
| Create key | [`POST /v1/api-keys`](/api-reference/user/create-api-key) |
| Revoke key | [`DELETE /v1/api-keys/{prefix}`](/api-reference/user/revoke-api-key) |

`{prefix}` is the `key_prefix` value returned by both list and create. It is the short leading
fragment of the key that listings expose in place of the full secret.

A new key can never grant a scope the creating credential does not already hold. A key with
`positions:read` cannot mint a key with `funds:withdraw`.

## Key states

| State | Behavior |
| --- | --- |
| Active | Valid and accepted. |
| Revoked | Manually revoked. Rejected with `401`. |
| Expired | Past its expiration date. Rejected with `401`. |

Revocation takes effect immediately. Webhook endpoints belong to your account rather than to the
key that created them, so revoking one key among several does not stop webhook delivery. See
[Webhooks](/guides/webhooks).
